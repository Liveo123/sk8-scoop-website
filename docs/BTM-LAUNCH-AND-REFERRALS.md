# Birthday Time Machine: draft launch and referral pilot (not approved for production)

Owner-approved commercial model: GBP 14.99 one-off price via Payhip, or one reward for three verified new SK8 Scoop newsletter subscribers.

## Payhip

- Seller has created a product with the confirmed URL `https://payhip.com/b/r5tML`.
- Stripe has a separate one-off product at GBP 14.99, but **Payhip must be connected to Stripe separately** to accept payments. Creating a Stripe product is not the same as connecting the payment gateway.
- Confirm the correct product ZIP has been uploaded to Payhip (v8 test pack, currently 9.1 MB), and **Payhip has the correct price/currency and description**.
- Product must stay Invisible until testing is authorised; Invisible means checkout does not work for buyers. For the approved test, set Unlisted, perform a 100% coupon checkout with a test buyer account, verify download and email, then return to Invisible until launch approval. Do not turn Invisible on again once actual paying customers need access to the file.
- At launch, use Payhip URL for the checkout, not the stand-alone Stripe Payment Link. Both have their own payment workflows; running both creates duplicate fulfilment/support work.

## Minimal subscriber referral pilot

- MailerLite custom field created on 17 October 2026: `birthday_time_machine_referral_code` (text, ID 1780628).
- No changes to existing `acquisition_channel` or first-touch attribution rules. This extra field records reward attribution separately.
- Assign personal random codes, `BTM-` followed by 8-12 uppercase letters/numbers. Codes are generated by the administrator, not derived from subscriber email or sequential count. Keep a private ledger; **never commit names/emails or codes to the public GitHub repository**.
- A referrer's share link has the format: `https://www.sk8scoop.com/adventures/birthday-time-machine/refer/?ref=BTM-<CODE>`.
- Link leads to a first-party newsletter signup page with existing Cloudflare Turnstile protection and submits to `/api/newsletter-signup`, which passes the field to MailerLite. No second mailing list, no public ZIP links.
- Referrer must be an existing active subscriber. Reader signs up personally. Never ask the referrer to upload or submit other people's email addresses.
- After signups, administrator checks that each subscriber is new after the code issuance, distinct, active, and not a self-referral, and separately assesses obvious abuse. Suggested safety review is seven days after signup. Do not promise a prize immediately on form completion.
- Once three qualify, issue a product-specific 100% Payhip coupon limited to ONE total use. Record coupon as issued/redeemed in the private ledger, and send to the claimant only after owner approval. Payhip's built-in product-sales referrals are **not** this newsletter referral programme.

## Limitations / checks before approval

1. Payhip cannot be controlled by the current ChatGPT connector. Owner must confirm Payhip checkout settings, uploaded file and actual receipt/download test.
2. The pages are staged code only, not published. Referral form depends on Cloudflare secrets in production, so preview-only browser tests do not verify real MailerLite writes.
3. Website signup endpoint accepts active MailerLite upserts. A successful form response does **not** prove net-new. Reward qualification must use created/subscribed date in MailerLite.
4. Currently codes are issued manually for a small initial pilot. Self-service generation and a reward dashboard should be considered only if this programme has enough demand.
5. Review privacy notice and final reward conditions before publishing. Public page must explicitly say referral codes are tracked, without exposing referees' identities.
6. Before selling, obtain a purchase-delivery receipt test, confirm tax treatment, update inconsistent duration/group numbers in Stripe and Payhip descriptions, and complete family QA. Current kit states ages 8-11, 4-12 children and 90-130 minutes including a break.
7. Current source code carries `noindex,nofollow` and mailto CTAs so the staged page is not a publicly open checkout.
8. Verify the existing shared `assets/site.js` leaves the custom referral field intact and retains first-touch attribution; confirm form uses exact `birthday_time_machine_referral_code` key when posted to `/api/newsletter-signup`.
9. Verify Turnstile action is `newsletter_signup`, because that is what the production worker enforces. The human check widget is enabled only for a syntactically valid code. Do not publish links with unassigned codes.
10. Run three acquisition QA cases: new valid email with assigned code, repeat existing email with assigned code (must not count), and invalid/unissued code (must not count). No test addresses should be treated as production growth.
